# Curso 50 — UX/UI Básico para Sitios y Apps

## Presentación del curso

UX/UI es una disciplina fundamental para crear sitios web, aplicaciones y productos digitales que no solo se vean bien, sino que sean claros, usables, accesibles y útiles para las personas. Muchas veces un proyecto falla no porque la idea sea mala ni porque el código esté roto, sino porque el usuario no entiende qué hacer, no encuentra la información, se frustra, abandona el formulario, no confía en la página o siente que la experiencia es confusa.

UX significa User Experience, o experiencia de usuario. Se enfoca en cómo una persona vive el uso de un producto: si entiende, avanza, logra su objetivo y siente confianza. UI significa User Interface, o interfaz de usuario. Se enfoca en los elementos visuales e interactivos: pantallas, botones, formularios, colores, tipografías, tarjetas, navegación, iconos y estados.

Este curso está pensado para principiantes: personas que diseñan páginas, desarrolladores web iniciales, emprendedores digitales, creadores de cursos, responsables de contenido, estudiantes, diseñadores autodidactas y cualquier persona que quiera mejorar la calidad de sus sitios o apps.

No busca formar diseñadores senior, sino dar una base sólida para pensar antes de diseñar, ordenar información, construir interfaces claras, evitar errores comunes y evaluar si una experiencia realmente funciona.

La idea central es:

> UX/UI no es decorar pantallas. Es diseñar caminos claros para que las personas puedan lograr objetivos con facilidad, confianza y comprensión.

---

## Objetivos de aprendizaje

Al finalizar este curso, el estudiante debería poder:

1. Comprender qué es UX y qué es UI.
2. Diferenciar experiencia de usuario, interfaz, usabilidad y accesibilidad.
3. Identificar necesidades, objetivos y problemas de usuarios.
4. Crear perfiles simples de usuario y escenarios de uso.
5. Organizar información mediante arquitectura básica.
6. Diseñar flujos de navegación claros.
7. Crear wireframes simples antes de diseñar visualmente.
8. Aplicar principios visuales de jerarquía, contraste, espaciado y consistencia.
9. Diseñar botones, formularios, tarjetas y navegación con criterio.
10. Entender estados de interfaz: carga, error, vacío, éxito.
11. Evaluar una página o app con heurísticas básicas.
12. Crear un prototipo simple de sitio o app con enfoque UX/UI.

# Módulo 1 — Qué es UX

## 1.1 Definición

UX, o experiencia de usuario, es la forma en que una persona percibe, entiende y utiliza un producto o servicio digital.

Incluye:

- facilidad de uso;
- claridad;
- utilidad;
- confianza;
- velocidad;
- accesibilidad;
- satisfacción;
- emociones;
- recorrido completo.

## 1.2 UX no es solo pantalla

La experiencia incluye todo el proceso:

- cómo llega el usuario;
- qué espera encontrar;
- qué entiende;
- qué hace;
- qué problemas aparecen;
- qué pasa después;
- si puede resolver su necesidad.

## 1.3 Ejemplo

Una tienda online puede tener un diseño visual atractivo, pero mala UX si:

- no muestra precios;
- el carrito es confuso;
- no aclara envíos;
- no confirma compra;
- tarda demasiado;
- no permite contactar;
- no genera confianza.

## 1.4 Objetivo de UX

El objetivo es reducir fricción y ayudar al usuario a lograr algo.

## 1.5 Pregunta central

> ¿La persona puede lograr su objetivo de manera clara, eficiente y confiable?

# Módulo 2 — Qué es UI

## 2.1 Definición

UI, o interfaz de usuario, es el conjunto de elementos visuales e interactivos con los que una persona se relaciona.

Incluye:

- botones;
- menús;
- formularios;
- colores;
- tipografías;
- iconos;
- tarjetas;
- modales;
- barras;
- inputs;
- mensajes;
- layout.

## 2.2 UI como lenguaje visual

La interfaz comunica jerarquía, importancia y acción.

Un botón destacado dice:

> esta acción es importante.

Un texto pequeño y gris dice:

> esto es secundario.

## 2.3 UI no es solo belleza

Una interfaz linda puede ser inútil si no se entiende.

## 2.4 Relación con UX

UX define la experiencia y el recorrido.
UI materializa esa experiencia en pantalla.

## 2.5 Ejemplo

UX:

> El usuario necesita inscribirse rápido a un curso.

UI:

> Botón claro “Inscribirme”, formulario corto, mensajes de error visibles y confirmación final.

# Módulo 3 — Usabilidad

## 3.1 Qué es usabilidad

La usabilidad mide qué tan fácil es usar un producto para alcanzar un objetivo.

## 3.2 Componentes

Incluye:

- facilidad de aprendizaje;
- eficiencia;
- prevención de errores;
- recuperación ante errores;
- satisfacción;
- claridad.

## 3.3 Señales de mala usabilidad

- el usuario pregunta qué hacer;
- abandona;
- comete errores repetidos;
- no encuentra botones;
- no entiende mensajes;
- tarda demasiado;
- necesita ayuda externa.

## 3.4 Señales de buena usabilidad

- entiende rápido;
- avanza sin instrucciones largas;
- encuentra información;
- corrige errores;
- completa tareas;
- confía en el proceso.

## 3.5 Regla

> Si hay que explicar demasiado cómo usar algo, probablemente la interfaz necesita mejorar.

---

# Módulo 4 — Accesibilidad e inclusión

## 4.1 Relación entre UX y accesibilidad

Una experiencia no es buena si excluye a parte de las personas.

## 4.2 Accesibilidad básica

Considerar:

- contraste;
- tamaño de texto;
- navegación con teclado;
- etiquetas en formularios;
- textos alternativos;
- lenguaje claro;
- foco visible;
- no depender solo del color.

## 4.3 Inclusión

Diseñar para diversidad:

- edades;
- niveles digitales;
- dispositivos;
- conectividad;
- capacidades;
- contextos;
- idiomas;
- experiencias previas.

## 4.4 Error común

Diseñar solo para usuarios expertos o para uno mismo.

## 4.5 Principio

> Una interfaz clara para personas con más barreras suele ser mejor para todos.

---

# Módulo 5 — Conocer al usuario

## 5.1 Por qué importa

No se diseña para “usuarios” en abstracto. Se diseña para personas con necesidades concretas.

## 5.2 Preguntas clave

- ¿quién usa esto?
- ¿qué quiere lograr?
- ¿qué sabe?
- ¿qué le preocupa?
- ¿desde qué dispositivo entra?
- ¿qué lo puede frustrar?
- ¿qué información necesita?
- ¿qué acción esperamos que complete?

## 5.3 Métodos simples

- entrevistas;
- observación;
- encuestas;
- revisión de comentarios;
- análisis de consultas;
- pruebas rápidas;
- feedback de clientes;
- datos de uso.

## 5.4 Usuario no es dueño del producto

El dueño puede querer mostrar todo. El usuario quiere resolver algo.

## 5.5 Resultado

Definir necesidades concretas antes de diseñar pantallas.

---

# Módulo 6 — Personas y escenarios

## 6.1 Qué es una persona

Una persona es un perfil representativo de usuario.

No es una caricatura. Es una herramienta para recordar para quién se diseña.

## 6.2 Ejemplo

> Marta, 58 años, usa celular, quiere inscribirse a un curso de trámites digitales, tiene poca confianza con formularios y necesita instrucciones claras.

## 6.3 Qué incluir

- nombre ficticio;
- edad aproximada;
- contexto;
- objetivo;
- dificultad;
- dispositivo;
- necesidad;
- expectativa.

## 6.4 Escenario

Un escenario describe una situación de uso.

Ejemplo:

> Marta entra desde el celular después de recibir un enlace por WhatsApp y quiere saber si el curso es gratuito, cuánto dura y cómo inscribirse.

## 6.5 Uso

Ayuda a decidir:

- qué información priorizar;
- qué lenguaje usar;
- qué pasos reducir;
- qué errores prevenir.

---

# Módulo 7 — Objetivos y tareas

## 7.1 Objetivo del usuario

Es lo que la persona quiere lograr.

Ejemplos:

- comprar un producto;
- inscribirse;
- leer una lección;
- descargar un PDF;
- pedir turno;
- consultar precio;
- comparar cursos.

## 7.2 Objetivo del negocio

Es lo que el proyecto espera.

Ejemplos:

- vender;
- generar contacto;
- educar;
- captar leads;
- reducir consultas;
- fidelizar;
- mostrar portfolio.

## 7.3 Alinear objetivos

Una buena UX conecta ambas partes.

Ejemplo:

Usuario quiere saber precio.
Negocio quiere vender.
Solución: precio visible, beneficio claro y botón de compra.

## 7.4 Tareas

Una tarea es una acción concreta:

- buscar curso;
- filtrar;
- abrir detalle;
- completar formulario;
- pagar;
- confirmar.

## 7.5 Mapa de tareas

Ordenar las tareas permite detectar pasos innecesarios.

---

# Módulo 8 — Arquitectura de información

## 8.1 Qué es

La arquitectura de información organiza contenidos para que sean encontrables y comprensibles.

## 8.2 Ejemplos

En una plataforma de cursos:

- Inicio;
- Rutas;
- Cursos;
- Lecciones;
- Recursos;
- Perfil;
- Ayuda.

## 8.3 Agrupar

Los contenidos deben agruparse por lógica del usuario, no solo por estructura interna del creador.

## 8.4 Navegación

Una buena navegación responde:

- dónde estoy;
- qué puedo hacer;
- cómo vuelvo;
- qué sigue;
- dónde encuentro ayuda.

## 8.5 Error común

Poner demasiadas opciones al mismo nivel.

---

# Módulo 9 — Flujos de usuario

## 9.1 Qué es un flujo

Un flujo describe los pasos que una persona sigue para completar una tarea.

## 9.2 Ejemplo: inscripción

1. Entra a curso.
2. Lee información.
3. Presiona inscribirme.
4. Completa formulario.
5. Confirma.
6. Recibe mensaje.

## 9.3 Detectar fricción

Preguntar:

- ¿hay pasos innecesarios?
- ¿se repite información?
- ¿falta feedback?
- ¿hay puntos de abandono?
- ¿el usuario sabe qué sigue?

## 9.4 Flujo feliz y errores

No diseñar solo el camino ideal. También diseñar:

- dato incorrecto;
- conexión lenta;
- formulario incompleto;
- curso agotado;
- pago rechazado;
- sesión vencida.

## 9.5 Principio

> Un buen flujo anticipa dudas y errores antes de que el usuario se frustre.

---

# Módulo 10 — Wireframes

## 10.1 Qué es un wireframe

Un wireframe es un boceto simple de pantalla.

Muestra estructura, no diseño final.

## 10.2 Para qué sirve

Permite pensar:

- jerarquía;
- contenido;
- navegación;
- acciones;
- layout;
- flujo.

## 10.3 Baja fidelidad

Puede hacerse en papel o con cajas simples.

## 10.4 Qué evitar

No empezar con colores, sombras e imágenes antes de resolver estructura.

## 10.5 Ejemplo

Una landing puede tener:

- hero;
- beneficios;
- prueba social;
- detalle;
- preguntas;
- CTA;
- footer.

---

# Módulo 11 — Jerarquía visual

## 11.1 Qué es

La jerarquía visual indica qué se ve primero, segundo y tercero.

## 11.2 Recursos

Se construye con:

- tamaño;
- peso;
- color;
- contraste;
- posición;
- espacio;
- agrupación;
- repetición.

## 11.3 Ejemplo

En una card de curso:

1. título;
2. beneficio;
3. nivel;
4. botón.

## 11.4 Error común

Todo tiene el mismo tamaño, color e importancia.

## 11.5 Regla

> Si todo grita, nada se escucha.

---

# Módulo 12 — Espaciado y alineación

## 12.1 Espacio como diseño

El espacio ayuda a separar, agrupar y respirar.

## 12.2 Alineación

Los elementos alineados se perciben más ordenados.

## 12.3 Consistencia

Usar una escala de espacios:

- 4;
- 8;
- 16;
- 24;
- 32;
- 48.

## 12.4 Agrupación

Elementos relacionados deben estar más cerca entre sí.

## 12.5 Error común

Llenar todos los espacios vacíos por miedo a que la pantalla “quede pobre”.

---

# Módulo 13 — Color y contraste

## 13.1 Color con función

El color debe comunicar, no solo decorar.

Usos:

- acción principal;
- alerta;
- éxito;
- estado;
- categoría;
- marca.

## 13.2 Paleta simple

Una interfaz inicial puede usar:

- color principal;
- color secundario;
- fondo;
- texto;
- borde;
- error;
- éxito.

## 13.3 Contraste

El texto debe leerse claramente.

## 13.4 No depender solo del color

Un error no debe indicarse solo en rojo. Debe tener texto.

## 13.5 Consistencia

El mismo color debe significar lo mismo en toda la interfaz.

---

# Módulo 14 — Tipografía y legibilidad

## 14.1 Tipografía

La tipografía influye en lectura y percepción.

## 14.2 Tamaños

Una escala simple:

- h1: grande;
- h2: medio;
- párrafo: legible;
- notas: menor, pero no ilegible.

## 14.3 Line-height

El interlineado mejora lectura.

## 14.4 Longitud de línea

Líneas demasiado largas cansan.

## 14.5 Texto UX

El texto de interfaz debe ser claro:

Malo:

> Proceder.

Mejor:

> Continuar inscripción.

---

# Módulo 15 — Botones y llamadas a la acción

## 15.1 Qué es CTA

CTA significa call to action, llamada a la acción.

Ejemplos:

- Inscribirme;
- Comprar ahora;
- Descargar guía;
- Ver curso;
- Solicitar turno;
- Guardar cambios.

## 15.2 Botón primario

Debe representar la acción principal.

## 15.3 Botón secundario

Acción menos importante.

## 15.4 Texto claro

Evitar botones genéricos como:

> Enviar

cuando puede ser:

> Enviar consulta

## 15.5 Estado

Los botones pueden tener:

- normal;
- hover;
- focus;
- disabled;
- loading.

---

# Módulo 16 — Formularios UX

## 16.1 Formularios como punto crítico

Muchos usuarios abandonan en formularios.

## 16.2 Reducir campos

Pedir solo lo necesario.

## 16.3 Labels claras

Cada campo debe tener etiqueta visible.

## 16.4 Mensajes de error

Deben explicar cómo corregir.

Malo:

> Error.

Mejor:

> Ingresá un correo válido, por ejemplo nombre@mail.com.

## 16.5 Confirmación

Después de enviar, mostrar qué pasó y qué sigue.

---

# Módulo 17 — Estados de interfaz

## 17.1 Cargando

Mostrar que algo está ocurriendo.

## 17.2 Vacío

Si no hay datos, explicar.

Ejemplo:

> Todavía no agregaste cursos favoritos.

## 17.3 Error

Informar y ofrecer acción.

Ejemplo:

> No pudimos cargar los cursos. Intentá nuevamente.

## 17.4 Éxito

Confirmar acción completada.

## 17.5 Disabled

Si una acción no está disponible, explicar por qué cuando sea posible.

---

# Módulo 18 — Patrones comunes

## 18.1 Cards

Agrupan información repetible.

## 18.2 Menús

Deben ser claros, consistentes y accesibles.

## 18.3 Modales

Usar con cuidado. Pueden interrumpir.

## 18.4 Tabs

Permiten organizar contenido relacionado.

## 18.5 Breadcrumbs

Ayudan a entender ubicación en sitios con muchas páginas.

## 18.6 Buscador y filtros

Útiles cuando hay mucho contenido.

---

# Módulo 19 — Heurísticas básicas

## 19.1 Qué son

Las heurísticas son principios para evaluar interfaces.

## 19.2 Visibilidad del estado

El sistema debe informar qué está pasando.

## 19.3 Coincidencia con el mundo real

Usar lenguaje familiar.

## 19.4 Control del usuario

Permitir volver, cancelar o corregir.

## 19.5 Consistencia

Mismos elementos deben comportarse igual.

## 19.6 Prevención de errores

Diseñar para evitar errores antes de que ocurran.

## 19.7 Reconocer antes que recordar

No obligar al usuario a memorizar información.

---

# Módulo 20 — Pruebas de usabilidad

## 20.1 Qué son

Pruebas donde personas intentan usar una interfaz para completar tareas.

## 20.2 Prueba simple

Pedir a alguien:

> Buscá un curso de JavaScript e intentá inscribirte.

Observar sin ayudar.

## 20.3 Qué observar

- dudas;
- clics equivocados;
- abandono;
- preguntas;
- errores;
- tiempo;
- comentarios.

## 20.4 No defender el diseño

Si el usuario no entiende, el problema es información valiosa.

## 20.5 Probar con pocas personas

Con 3 a 5 personas ya pueden aparecer problemas importantes.

---

# Módulo 21 — UX/UI en proyectos educativos

## 21.1 Plataforma de cursos

Debe facilitar:

- encontrar cursos;
- entender nivel;
- iniciar aprendizaje;
- continuar progreso;
- leer lecciones;
- hacer actividades;
- descargar recursos;
- pedir ayuda.

## 21.2 Problemas comunes

- cursos difíciles de encontrar;
- lecciones largas sin estructura;
- progreso confuso;
- botones poco claros;
- navegación inconsistente;
- textos densos;
- mala lectura en móvil.

## 21.3 Mejoras

- rutas claras;
- buscador;
- tarjetas bien jerarquizadas;
- progreso visible;
- lecciones escaneables;
- CTA claro;
- diseño responsive;
- accesibilidad.

## 21.4 Confianza

Un sitio educativo debe transmitir orden y seriedad.

## 21.5 Cursoteca como caso

Una cursoteca profesional necesita combinar contenido, navegación, identidad visual y arquitectura escalable.

# Caso práctico integrador

## Caso: rediseño de una página de cursos

Una página muestra muchos cursos, pero los usuarios no saben por dónde empezar.

### Paso 1 — Problema

El contenido existe, pero la navegación es confusa.

### Paso 2 — Usuario

Persona adulta que quiere aprender herramientas digitales desde cero.

### Paso 3 — Objetivo

Encontrar un curso inicial y comenzar.

### Paso 4 — Arquitectura

Organizar por rutas:

- Ciudadanía Digital;
- Trabajo e IA;
- Datos;
- Emprendimiento;
- Desarrollo Web.

### Paso 5 — Wireframe

Página principal con:

- buscador;
- rutas;
- cursos destacados;
- guía “empezá por aquí”;
- progreso.

### Paso 6 — UI

Tarjetas claras, botones visibles, contraste, tipografía legible.

### Paso 7 — Prueba

Pedir a una persona encontrar “JavaScript desde Cero”.

### Resultado

La página mejora porque reduce incertidumbre y orienta al usuario.

# Glosario básico

UX: experiencia de usuario.

UI: interfaz de usuario.

Usabilidad: facilidad con la que una persona usa un producto para lograr un objetivo.

Accesibilidad: capacidad de ser usado por personas con distintas capacidades y contextos.

Persona: perfil representativo de usuario.

Escenario: situación concreta de uso.

Flujo de usuario: pasos para completar una tarea.

Arquitectura de información: organización del contenido.

Wireframe: boceto estructural de una pantalla.

Prototipo: representación navegable o simulada de una solución.

Jerarquía visual: orden de importancia visual de elementos.

CTA: llamada a la acción.

Estado de interfaz: situación como carga, error, vacío o éxito.

Heurística: principio para evaluar usabilidad.

Prueba de usabilidad: observación de usuarios reales intentando completar tareas.

Design system: conjunto de reglas y componentes visuales reutilizables.

# Producto final del curso

Al finalizar, el estudiante debe crear un **Prototipo Básico UX/UI**.

Ese producto debe permitir:

- entender al usuario;
- definir una tarea;
- ordenar información;
- diseñar un flujo;
- crear wireframes;
- aplicar jerarquía visual;
- diseñar componentes;
- contemplar estados;
- revisar accesibilidad;
- probar con usuarios;
- justificar mejoras.

El curso termina cuando la persona deja de diseñar pantallas “porque se ven lindas” y empieza a diseñar experiencias claras, usables, inclusivas y orientadas a objetivos.
